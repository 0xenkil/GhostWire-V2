## TASK 2 — Folder-wise bug analysis

### core/
- **`result_contracts.py` — `partial_success` normalized to `UNKNOWN` (FIXED).** The enum has `PARTIAL="partial"` but no `partial_success`, and the alias map omitted it, so any `ToolResult(status="partial_success")` silently became `UNKNOWN` (→ `success=False`), discarding the "produced data despite WAF" signal. Added alias `"partial_success" → ResultStatus.PARTIAL`. *(Latent follow-up: tool_manager sets the raw string `result.status = "partial_success"` by attribute assignment, which bypasses `__post_init__` normalization — harmless today because comparisons are against string literals on a `str`-Enum, but worth standardizing to the enum.)*
- `wsl_executor.py` / `ssh_executor.py` — smarter stall killer added (C1). `subprocess.run` call sites carry timeouts; streaming `Popen` paths bound by manual timeout loops — OK.
- `orchestrator.py` — sync/async `agent.run()` dispatch and `asyncio.timeout`/`TaskGroup` handling reviewed; correct for the 3.11+ API.

### agents/
- **`exploitation_agent.py` — scope check failed OPEN (FIXED, security-relevant).** In host auto-expansion, if `scope.is_in_scope()` raised, the `except: pass` fell through to `new_hosts.add(m)`, adding an **unverified** host to the attack surface. Changed to fail **closed** (`continue` on error). The "no scope object configured" path is preserved.
- `base_agent.py` — dead no-op status expression removed (C4); other `except: pass` sites (foothold scan, gobuster canonicalization, env-constraint build) reviewed and judged benign defensive swallows with safe fallbacks.

### tools/
- `tool_manager.py` — success/false-success logic (`_produced_real_output`, deterministic-no-retry guard, partial-success handling) is well-formed and is the correct single authority; C3 aligns base_agent to defer to it.

### intelligence/

### utils/ , config/
- `logger.py` — redundant local `import logging` (F811) shadowing the module import; cosmetic, left as-is.
- No correctness bugs found.

## TASK 3 — Make it reason like a human operator (the "write-only brain")

**Diagnosis (graphify + call-site analysis):** the engine has all the cognitive
organs — `StrategicAdvisor`, `SelfAwarenessModule`, `ReasoningEngine`,
`HypothesisEngine` — but they were a **write-only brain**: ~5 sites FEED outcomes
in (`record_tool_outcome`/`register_finding`), **0 sites READ their advice** to
make a decision. graphify's honest audit trail flagged it — every
`BaseAgent → {advisor, awareness, reasoning}` edge was `INFERRED`, not
`EXTRACTED`. The loop was steered by mechanical counters (3-timeout ban,
`_consecutive_empty_loops>=2`, `max_repairs`). `think()` injected only the brain's
PASSIVE vitals ("3 facts, 1 contradiction, medium confidence"), never its ACTIVE
advice. → that's why a run brute-forced `nmap -p-` 7× against a Vercel/CDN edge
instead of pivoting to web/API testing.

**Fix (no hardcoding — "give the AI better evidence, don't branch in code"):**
- `intelligence/strategic_advisor.py`: `advise_tool_selection` /
  `advise_discovery_order` gained `full=True` to return the whole advice dict
  (tool recs + `strategic_pivot_suggestions` + `warning_signs` + `knowledge_gap`
  + `early_exit_conditions`), not just the tool list. Removed a dead no-op
  `f"{tool}@{target}"` in `should_continue_trying`.
- `agents/base_agent.py`: new `_situation_summary()` + `_strategic_advice_note(phase)`,
  wired into `think()`'s existing (throttled) `_inject_awareness` block. Injects,
  as EVIDENCE for the deciding AI: `RECOMMENDED` tools, `AVOID`, `STOP-SIGN`,
  `PIVOT`, `KNOWLEDGE-GAP`, `EARLY-EXIT`, `COLLECT-NEXT`. The advisor's AI call is
  cached per (phase, tech-stack) → ≤1 extra round-trip per situational shift.

End-to-end verified: a stub AI returning CDN/SPA advice yields a note that says
*AVOID nmap (CDN filters all ports) → PIVOT to web/API → EARLY-EXIT on login
panel*. The main loop's AI still decides; the brain is evidence only.

**Also wired:** `ReasoningEngine.analyze_tool_failure` was a hardcoded substring
stub that ignored its own AI backend — made it AI-driven (heuristic only as the
no-AI fallback) and added an `is_approach_wrong`/`suggested_pivot` verdict. It now
fires from `_track_failure` **once** when a `(tool@host)` hits 3 failures, upgrading
`_recent_failures` (already injected into the next decision prompt) from a raw error
string to a reasoned *"flag changes won't help — PIVOT"* signal. Bounded to one
extra AI call per stuck tool. Verified both paths + 138 tests pass.

## TASK 4 — Adaptive phase plan (fenced)

`core/orchestrator.py`: after the existing dependency gate, an OPTIONAL phase can
now be skipped when the AI judges it pointless for THIS target (e.g. persistence /
weaponization on a stateless serverless/CDN site). Hard fences:
- `_MANDATORY_PHASES = {planning, recon, exploitation, reporting}` always run.
- `_phase_applicable()` **fails OPEN** — any AI error / malformed response /
  ambiguity RUNS the phase, so it can only ever prune clearly-dead work, never
  starve a needed phase. Cached → ≤1 AI call per phase. The AI decides (no
  hardcoded per-target logic); code only guarantees the conservative default.

## TASK 6 — Intent-vs-reality analysis ("how should it work — does it?")

Behavioral analysis of critical contracts (code that *runs fine but does the
wrong thing*). Four real bugs found and fixed:

1. **Strategic brain read the wrong findings source.** `_situation_summary()`
   (feeds the advisor's tech-stack) read per-instance `self._findings`, which
   only holds the CURRENT agent's findings — so during **exploitation** it was
   blank (recon's tech stack lives in the cross-phase DB `self.store`). Now reads
   `store.get_all_findings()` first. Also fixed the tech extraction: findings are
   stored `"CMS: WordPress"`, and `.split()[0]` yielded `"cms:"` not the tech
   name — now takes the part after the `label:`.
2. **Syntax learner re-poisoned the wordlist.** `_abstract` placeholdered the
   directory but kept the filename, so a workspace host-list mis-used as `-w`
   (`-w <WORKDIR>/recon_hosts.txt`) got memorized and re-suggested — fighting the
   C2 wordlist rule. Now a *workspace* file used as `-w`/`--wordlist` abstracts to
   the `{WORDLIST}` token (generic, any tool); applied on both learn AND reuse so
   existing poisoned entries self-heal. Real `/usr/share/...` wordlists untouched.
3. **"Make command lighter" didn't reduce workload.** On nmap timeout it produced
   `-p- --min-parallelism 10/5` — kept all 65 535 ports (the real cost) and even
   *raised* parallelism. The prompt framed "lighter" as concurrency, not BREADTH.
   Rewrote it to make the AI cut breadth first (ports/wordlist/targets) and never
   raise parallelism. Still AI-driven, no hardcoded command.
4. **Scope-enforcement bypass (security).** `check_target`'s contract is "before
   EVERY tool execution", but the call site gated on `if target:` — so a command
   with `target=None` skipped the check entirely, and it validated the declared
   `target` rather than the host the command hits. Now falls back to the command's
   real host when `target` is absent (fail-closed); local `--help` calls (no host)
   are correctly left alone.

Locked by `tests/test_intent_fixes.py` (4 tests). **Suite: 154 passing.**

## TASK 7 — Universal AI outcome triage (the "handle anything unseen" capability)

**The pattern behind most bugs this session:** consequential decisions made by
HARDCODED substring lists / fixed thresholds (`failure_sigs`,
`_DETERMINISTIC_FAIL`, `syntax_errors`, `known_partial_success = {6 named tools}`,
"3 timeouts → ban"). Those can't generalize — a novel tool, a never-seen error
format, or a new defense falls through to a brittle default. That is the core
barrier to "handle any new issue seamlessly".

**Fix (`agents/base_agent.py` `_interpret_outcome`, wired in `safe_run_tool`):** a
single, tool-agnostic AI triage. For any NON-success result, the AI reasons from
first principles (explicitly told it may be a tool/error it has never seen) and
returns one action:
- **accept** — the output already holds useful results → salvage it, for ANY
  tool, with no hardcoded tool whitelist (cures "novel tool exits non-zero by
  convention → output discarded").
- **abandon** — a genuinely non-recoverable failure for this target → stop
  burning the repair budget, with no hardcoded deterministic-error list.
- **repair** — falls through to the existing AI `--help` repair flow (unchanged).

It only ADDS the `accept`/`abandon` shortcuts; every other path is untouched.
Bounded + fail-safe: cached per (tool, error-signature) so a novel error is
reasoned about ONCE per engagement (repeats reuse the verdict, no AI call); any
error or missing AI backend → `repair` (today's default). The hardcoded lists now
act only as a cheap first pass, never the final authority. Locked by
`tests/test_ai_outcome_triage.py` (5 tests). **Suite: 159 passing.**
